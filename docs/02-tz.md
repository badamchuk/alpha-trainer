# ТЗ: система вправ, замін і конструктора тренувань

_Версія 2. 2026-09-17. Враховано незалежну рецензію — рішення в `docs/03-tz-review.md`._

## 1. Мета й межі

Зробити вправу об'єктом, який додаток розуміє, і на цій основі дати: вибір вправ із картинками,
грамотну заміну вправи, конструктор тренування і правильні розрахунки.

**MUST:** бібліотека (F1), розпізнавання назв (F2), каталог і картка (F3), заміни (F4),
конструктор (F5), ілюстрації (F6), аналітика за ідентифікатором (F7).
**SHOULD:** план і профіль (F8).
**Поза межами:** нутриція, синхронізація, інтеграції з годинниками, UI-тести, рефакторинг
спільної форми вправи, зміни промптів AI-тренера (він і далі бачить сирі назви).

## 2. Терміни

- **Вправа** — запис бібліотеки з незмінним `id`.
- **Патерн руху** — тип руху; основа спорідненості.
- **Сімейство** — варіації одного руху (підтягування: з резинкою, негативні, строгі, до грудей).
- **Рівень 1–3** — 1 полегшена, 2 базова, 3 складна; порівнюється лише всередині спорідненості.
- **Намір (`intent`)** — для чого вправа: максимальна сила, гіпертрофія, потужність, кондиція,
  ізометрія, мобільність. Визначає схему підходів.
- **Зона берегти** — ділянка (плече, поперек, коліно, зап'ястя, лікоть), навантаження на яку
  користувач просить уникати.

## 3. Модель даних

### 3.1 Бібліотечна вправа

```ts
type Level = 1 | 2 | 3;
type Intent = 'max_strength' | 'hypertrophy' | 'power' | 'conditioning' | 'isometric' | 'mobility';
type Metric = 'weight_reps' | 'reps' | 'time' | 'distance' | 'calories';
type JointZone = 'shoulder' | 'lower_back' | 'spine_flexion' | 'spine_extension' | 'knee' | 'wrist' | 'elbow';

interface LibraryExercise {
  id: string;                       // 'pull_up' — НЕЗМІННИЙ між версіями
  nameUk: string; nameEn: string;
  aliases: string[];                // синоніми, написання й помилки, у нормалізованій формі
  ambiguous?: boolean;              // назва сама по собі неоднозначна → лише ручна прив'язка
  pattern: MovementPattern;
  secondaryPattern?: MovementPattern;   // для складених рухів (трастер = squat + push_vertical)
  family: string;                   // сімейство варіацій
  level: Level;
  intent: Intent;
  metKind: ExerciseKind;            // готове значення для services/calories.ts
  metrics: Metric[];                // як записується; перша — основна
  equipment: Equipment[];           // потрібне ВСЕ; [] = власна вага
  muscles: { primary: Muscle[]; secondary?: Muscle[] };
  stress?: Partial<Record<JointZone, 1 | 2 | 3>>;  // 3 — жорсткий відсів, 2 — понижуємо, 1 — ігноруємо
  easierThan?: string[];            // ця вправа простіша за перелічені (працює між сімействами)
  modifications?: string[];         // «те саме, але…»: інший снаряд, хват, амплітуда
  cues: string[];                   // 2–4 підказки техніки українською
  defaultReps?: number;             // типові повтори (для конструктора)
  defaultSeconds?: number;          // типовий час (планки, стільчик)
  cardio?: { modality: CardioModality; per2min: { distanceM?: number; calories?: number; reps?: number } };
  imageSlug?: string;               // ключ у мапі ілюстрацій (сама мапа — в UI-модулі)
}
```

Перелічення `MovementPattern`, `Equipment`, `Muscle`, `CardioModality` — як у додатку A.
`ExerciseKind` береться з наявного `services/calories.ts`.

**Обсяг:** ~150 вправ. Обов'язково:
1. **усі 152 назви з історії користувача**, які є вправами (як `id` або як `alias`);
2. кросфіт-набір: бурпі (+ полегшені), трастер, wall ball, стрибки на бокс, сітап, T2B, махи гирею,
   ривок гантелі, девіл прес, фермерська хода, гребний/лижний/байк/скакалка, стільчик біля стіни;
3. базові силові з варіаціями (штанга/гантелі/тренажер/власна вага) і повними ланцюжками
   прогресій для підтягувань, віджимань, присідань, планок, брусів;
4. ≥ 10 рухів розминки й мобільності.

### 3.2 Зміни в наявних типах

```ts
interface ExerciseLog {          // лише доповнення
  exerciseId?: string;           // безумовний пріоритет над зв'язком за назвою
}

interface UserProfile {
  equipmentIds?: Equipment[];    // нове; старе equipment: string[] лишається для сумісності
  protectZones?: JointZone[];    // постійні обмеження (за замовчуванням порожньо)
}

interface CustomExercise {
  id: string;                    // 'custom_…'
  name: string;
  baseId?: string;               // «схожа на» — звідки беруться патерн, м'язи, обладнання, stress
  createdAt: string;
}
```

**Нові ключі сховища** (усі — в `services/backup.ts` ALL_KEYS):
`@alpha_trainer:exercise_links`, `@alpha_trainer:custom_exercises`, `@alpha_trainer:builder_draft`.

## 4. Функціональні вимоги

### F1. Бібліотека

- **F1.1** Дані — типізовані TS-модулі, згруповані за патернами; єдиний реєстр з **лінивими**
  індексами (за id, нормалізованою назвою й синонімом, патерном, сімейством, м'язом), які
  будуються при першому запиті, а не при імпорті модуля.
- **F1.2** Тест цілісності: унікальні `id`; синоніми унікальні між вправами, **крім** позначених
  `ambiguous` (для них тест вимагає, щоб автоприв'язка не спрацьовувала); усі `easierThan`
  посилаються на наявні id і не утворюють циклів; обов'язкові поля заповнені; `cues` ≥ 2;
  `cardio` задано тоді й лише тоді, коли `pattern = 'monostructural'`; у складених рухів
  заданий `secondaryPattern`; `metKind` входить у перелік `ExerciseKind`.
- **F1.3** Незмінність: `id` не перейменовуються й не видаляються між версіями; окремий тест
  перевіряє, що всі id зі збережених зв'язків існують у бібліотеці.
- **F1.4** Сумісність: `MuscleGroup` (12 груп) виводиться з `muscles.primary` **однією** мапою
  `Muscle → MuscleGroup`; групи балансу й об'ємних орієнтирів виводяться з неї, а не окремо.
- **F1.5** Семантичне ревʼю: до злиття згенерувати таблицю `назва / сімейство / рівень / intent /
  stress / easierThan` для топ-40 вправ користувача і затвердити її очима.

### F2. Розпізнавання назв

- **F2.1 Нормалізація:** нижній регістр; уніфікація апострофів (`'`, `ʼ`, `’`); зрізання пунктуації,
  чисел і одиниць («400м», «1 хв», «×10»); злиття пробілів; зрізання службового тексту з AI-плану
  (рядки з часом «17:00», заголовки, що закінчуються двокрапкою). Для нечіткого порівняння
  додатково: и↔і, ґ↔г, ё↔е, латиниця↔кирилиця у змішаних назвах.
- **F2.2 Пошук:** 1) зв'язок користувача → 2) точний збіг назви/синоніма → 3) нечіткий збіг
  **лише якщо точний дав 0**: за множиною слів, поріг на слово — відстань Дамерау-Левенштейна ≤ 1
  для слів ≤ 5 символів і ≤ 2 для довших; збіг приймається, якщо зіставлено ≥ 60% слів і немає
  другого кандидата з таким самим рахунком.
- **F2.3** Неоднозначні назви (`ambiguous`, напр. «присідання») **не** прив'язуються автоматично —
  лише через F2.6. Контекстних правил немає.
- **F2.4** Результат: `{ id, confidence: 'link' | 'exact' | 'alias' | 'fuzzy' | 'none' }`.
  Автоматично діють `link`, `exact`, `alias`; `fuzzy` — тільки підказка.
- **F2.5** Записи не переписуються: назва користувача лишається; `exerciseId` у записі має
  безумовний пріоритет над зв'язком за назвою.
- **F2.6 Екран «Нерозпізнані вправи»** (Профіль): назви з кількістю записів, підказка-кандидат,
  дії «Це воно» / «Обрати іншу» / «Моя власна вправа». Перед застосуванням — попередження
  «вплине на N записів»; при першому вході — пропозиція зробити резервну копію.
- **F2.7 Журнал зв'язків:** список чинних зв'язків (назва → вправа, кількість записів), дія
  «Відв'язати», позначка «сирітський» для зв'язків на неіснуючі id.
- **F2.8 Власні вправи:** без `baseId` не беруть участі в замінах і в конструкторі; з `baseId`
  успадковують патерн, м'язи, обладнання, `stress`, `level`, `intent`, `metKind`.

### F3. Каталог і картка вправи

- **F3.1** Пошук за нормалізованою назвою й синонімами обома мовами, стійкий до однієї помилки
  (правила F2.2).
- **F3.2** Фільтри: група м'язів, патерн, обладнання, рівень, перемикач «лише доступне мені».
- **F3.3** Секції: «Нещодавні» (8 останніх вправ користувача; за відсутності історії — сховано)
  і повний список.
- **F3.4** Рядок: мініатюра (кадр 1), назва, група м'язів, обладнання, рівень. Список — `FlatList`
  з `getItemLayout`, `windowSize`, `removeClippedSubviews`.
- **F3.5** Вибір повертає `{ id, name }`; `name` — мовою налаштування назв вправ. Дефолт мови
  змінюється на `uk` (міграція для тих, хто не чіпав налаштування). Каталог доступний і у формі
  запису тренування, і в редагуванні збереженого тренування (`app/workout/[id].tsx`, де зараз
  лише текстове поле).
- **F3.6 Картка:** анімована ілюстрація, обидві назви, м'язи, обладнання, рівень, намір, 2–4
  підказки техніки, «Те саме, але…» (`modifications`), блоки «Простіше» / «Варіації» /
  «Складніше», моя історія (3 останні результати, рекорд), кнопка «Відео» (пошук на YouTube,
  неактивна без мережі).

### F4. Заміна вправи

- **F4.1 Точки входу:** форма запису, режим шаблону, редагування збереженого тренування,
  конструктор, день плану, картка вправи.
- **F4.2 Панель заміни:** вихідна вправа; чипси «Немає обладнання», «Берегти плече / поперек /
  коліно / зап'ястя / лікоть», «Просто не хочу»; однорядковий дисклеймер: «Гострий або тривалий
  біль — привід до лікаря, а не до заміни вправи». Обмеження діють **на цю сесію**; постійні
  беруться з `profile.protectZones`, якщо задані. Блоки: «Те саме, але…» (`modifications`),
  «Простіше» (до 5), «Варіації» (до 6). Блоку «Складніше» тут немає — прогресії в картці вправи.
- **F4.3 Відбір кандидатів:**
  1. обладнання: усе потрібне доступне (профіль мінус «немає сьогодні»);
  2. зони: відсіюються `stress[зона] = 3`; `= 2` дозволені, але з позначкою й нижче в сортуванні;
  3. спорідненість: `candidate.easierThan` містить оригінал (явно простіша), або те саме
     `family`, або той самий `pattern` (для складених рухів — збіг обох патернів або сімейства);
  4. блок: явні зв'язки — в «Простіше»; далі за рівнем: нижчий → «Простіше», однаковий → «Варіації»;
  5. сортування: явні зв'язки → те саме сімейство → той самий `intent` → перетин м'язів (Жаккар;
     для кардіо — спорідненість модальності) → менша різниця рівня → знайомість (скільки разів
     робив) → id;
  6. власні вправи без `baseId` виключені.
- **F4.4 Пояснення** до кожного варіанта генерується з різниці: «те саме, але з гантелями»,
  «з допомогою резинки», «простіша техніка», «не навантажує плече», «помірно навантажує поперек».
- **F4.5 Перенесення припису:** якщо `intent` збігається — підходи й повтори лишаються;
  якщо `intent` інший — схема береться з правил F5.4 для нового наміру, і UI пише «схему підходів
  оновлено». Вага очищується при зміні обладнання; разом з нею очищується `setsDetail` (повтори
  зберігаються). Якщо для нової вправи є історія — підставляється остання робоча вага.
- **F4.6** Заміна зберігає позицію вправи в списку й членство в суперсеті.
- **F4.7** Якщо кандидатів немає — чесне повідомлення без випадкових пропозицій.
- **F4.8 Конверсія кардіо.** Якір — **2 хвилини роботи в помірно-важкому темпі**:
  біг 400 м · гребний 500 м · лижний 500 м · BikeErg 1000 м · air bike 20–25 ккал ·
  гребний 25 ккал · скакалка 200 стрибків. Перерахунок застосовується до значення **одного
  підходу**; кількість підходів не змінюється. Результат округлюється (25/50/100 м, 5 ккал,
  10 стрибків). У підписі — «орієнтовно, для чоловіка ~80 кг».

### F5. Конструктор тренування

- **F5.1 Формати:** «Кросфіт» (пишеться як `workoutType: 'crossfit'`) і «Фулбоді»
  (`workoutType: 'strength'`). Тривалість 30 / 45 / 60 хв. Фокус (лише для Фулбоді):
  сила / маса / витривалість.
- **F5.2 Структура — слоти.** Фулбоді 60 хв: розминка (кардіо + 2 мобільності) → A основна
  (`squat` або `hinge`) → B основна (`push_horizontal` або `pull_vertical`) → C суперсет
  (протилежний до B + `lunge`/`hip_thrust`) → D кор → заминка. 45 хв — без D; 30 хв — A, B, кор.
  Кросфіт 60 хв: розминка 8 хв → силова частина 15 хв (один рух зі штангою або гирею) →
  метокон 8–15 хв → кор і заминка 5 хв. 45 хв — силова 12 хв, метокон 10–12 хв; 30 хв — без
  силової, метокон 12–15 хв.
- **F5.3 Вибір вправи в слот:** фільтри як у F4.3 (обладнання, зони, рівень ≤ рівня користувача);
  оцінка = відповідність патерну слота + знайомість + влучання в рівень − повтор сімейства в цьому
  тренуванні − повтор основної вправи з двох попередніх тренувань того самого формату.
  Сигнатура детермінована: `generate(input, seed, attempt)`; «перегенерувати» збільшує `attempt`.
- **F5.4 Приписи:**
  - Фулбоді: сила 5×3–5 (відпочинок 150 с), маса 4×6–8 (120 с), витривалість 3×12–15 (60 с);
    допоміжні 3×8–12 (75 с); кор — `defaultSeconds` або `defaultReps`, 3 підходи (45 с).
  - Кросфіт: силова частина 5×3 / 5×5 / EMOM 10; метокон — 2–4 рухи, схеми «AMRAP N хв»,
    «21-15-9», «5 раундів», «EMOM N хв»; повтори за метрикою руху: з обтяженням 9–15, власна
    вага 10–20, кардіо 200–400 м бігу або еквівалент за F4.8.
  - Вага: остання робоча з історії для цієї вправи; якщо історії немає — ваги не пропонуємо,
    показуємо цільовий RPE (сила 7–8, маса 7, витривалість 6–7).
- **F5.5 Час** рахується тією самою моделлю, що й калорії (`services/calories.ts`), а не окремою
  формулою; результат має вкладатись у задану тривалість ±15%, інакше зменшується кількість
  допоміжних слотів або підходів.
- **F5.6 Результат:** чернетка `{ workoutType, focus, durationMin, blocks[], estimatedMinutes,
  estimatedKcal }`, де блок = { роль, заголовок, нотатка (напр. «AMRAP 12 хв»), вправи }.
  Метокон записується суперсетом, підходи = раунди.
- **F5.7 Дії:** замінити вправу (F4), перегенерувати слот, перегенерувати все, додати/видалити
  вправу, зберегти як шаблон, почати тренування (форма запису відкривається заповненою).
  Чернетка зберігається в `builder_draft` і переживає вихід з екрана; при старті тренування
  або явному скиданні — очищується. Якщо після фільтрів слот порожній — слот показується
  з поясненням «немає підхожої вправи під твоє обладнання», решта тренування будується далі.

- **F6.6** Мапа ілюстрацій імпортується **лише** з UI-компонентів; `services/exercises.ts`,
  `analytics.ts`, `calories.ts` про неї не знають (інакше тести тягнутимуть ассети).

### F7. Аналітика за ідентифікатором

- **F7.1 Контракт:** `type ExerciseResolver = (log: ExerciseLog) => string | null`. Передається
  **останнім необов'язковим** аргументом у `getExerciseProgress`, `getAllExerciseNames`,
  `getPersonalRecords` (в `analytics.ts` і `storage.ts`), `getOverloadSuggestion`,
  `getMuscleGroupBalance`, `getVolumeLandmarks`, `getStrengthScore`, `estimateWorkoutCalories`.
  Без резолвера поведінка не змінюється. Екран будує резолвер один раз із зв'язків і власних вправ.
- **F7.2** Записи з однаковим id зливаються в один рядок прогресу; у списках прогресу показується
  бібліотечна назва, у самому записі тренування — та, що набрав користувач.
- **F7.3 Об'єм і баланс:** у підрахунок ідуть лише вправи з `intent` `max_strength` або
  `hypertrophy` (по 1 підходу), `power` — з коефіцієнтом 0.5, решта (`conditioning`, `isometric`,
  `mobility`) — 0. Це прибирає перекіс від кросфіт-метоконів і працює й для старої історії.
- **F7.4 Калорії:** якщо вправу впізнано — вид береться з `metKind`; інакше працює наявна
  логіка за назвою. Наявні тести калорій лишаються без змін.
- **F7.5 Звіт «до/після»** на копії реальних даних з метриками: впізнаних записів, сума калорій
  за 30 тренувань, підходи на групу за типовий тиждень, кількість рядків прогресу. Розходження
  понад 20% по калоріях або по підходах пояснюється в звіті.

### F8. План і профіль (SHOULD)

- **F8.1** Вправи плану розпізнаються через F2; у дні плану — мініатюри й кнопка «Замінити».
- **F8.2** «Почати тренування за планом» відкриває форму запису, заповнену вправами дня.
- **F8.3 Профіль:** обладнання групами (вільна вага / тренажери / гімнастика / кардіо) з пресетами.
  «Тренажерний зал» = `barbell, dumbbell, ez_bar, plate, bench, cable, machine, smith, pullup_bar,
  dip_bars, treadmill`; «Кросфіт-зал» = все попереднє + `kettlebell, box, wall_ball, rings, band,
  rower, air_bike, ski_erg, jump_rope, medicine_ball`. Міграція старих значень: «Штанга»→`barbell`,
  «Гантелі»→`dumbbell`, «Гирі»→`kettlebell`, «Турнік»→`pullup_bar`, «Брусся»→`dip_bars`,
  «Еспандер»→`band`, «Скакалка»→`jump_rope`, «Бігова доріжка»→`treadmill`,
  «Тренажерний зал»→пресет, «Лише власна вага»→`[]`.
- **F8.4** Поле постійних «берегти зони» в профілі (порожнє за замовчуванням).

## 5. Нефункціональні вимоги

- **N1 Офлайн:** усе, крім «Відео» й AI, працює без мережі.
- **N2 Швидкодія:** індекси ліниві; нечіткий пошук лише коли точний дав 0; каталог — віртуалізований
  список; картинки не вантажаться поза екраном.
- **N3 Розмір:** APK росте не більше ніж на 5 МБ (зараз 50.2 МБ, і оновлення качається цілком).
- **N4 Дані:** міграції лише додають; назви користувача не змінюються; нові ключі в бекапі;
  при імпорті бекапу відсутні в ньому ключі очищаються; читання через `readJSON`, запис — `withLock`.
- **N5 Детермінованість:** рушії — чисті функції; `generate(input, seed, attempt)`.
- **N6 Тести:** цілісність бібліотеки (F1.2, F1.3); розпізнавання, включно з фіксованим набором
  реальних пар («крокуючий випадок»/«крокуючі випади», «front squad»/«front squat»,
  «sit up»/«сітап»/«situp», «стільчик біля стіни»/«стільчик під стінкою»/«присідання під стіною»);
  заміни (топ-20 вправ, фільтри обладнання й зон, конверсія кардіо, зміна наміру); конструктор
  (2 формати × 3 тривалості × фокуси); аналітика з резолвером і без. Наявний 101 тест лишається
  зеленим.
- **N7 UI:** українська, темна тема, `insets.top` у шапках, `KeyboardAvoidingView` у модалках,
  зони натискання ≥ 44 dp.
- **N8 Право:** лише перевірені ліцензії; авторство в додатку й у репозиторії; дисклеймер про біль.
- **N9 iOS:** WebP у стандартному `Image` на iOS може не декодуватись — обмеження зафіксувати в
  документації (реліз зараз лише Android).

## 6. Критерії приймання

| # | Критерій | Перевірка |
|---|---|---|
| A1 | ≥ 70% записів історії (з 286) прив'язуються автоматично; ≥ 95% — після одного проходу екраном F2.6 | Скрипт на копії реальних даних |
| A2 | Для кожної з топ-20 вправ користувача є ≥ 2 «простіше» і ≥ 2 «варіації» (де такі існують), усі — спорідненого руху | Unit-тест |
| A3 | Жодна пропозиція не порушує фільтр обладнання й не містить `stress = 3` по обраній зоні | Unit-тест на всій бібліотеці |
| A4 | Конструктор: 2 формати × 3 тривалості × фокуси дають тренування в межах ±15% часу, без повторів сімейств, лише з доступним обладнанням; результат детермінований | Unit-тест |
| A5 | Прогрес зливає дублі; рекорди, об'єм і калорії рахуються за бібліотекою; метокони не роздувають об'єм | Unit-тест + звіт F7.5 |
| A6 | Ілюстрації є для ≥ 60% бібліотеки і ≥ 70% топ-30 вправ користувача; екран авторства присутній | Скрипт підрахунку + скріншот |
| A7 | 101 наявний тест зелений, typecheck без помилок, APK +≤ 5 МБ | `npm test`, `npm run typecheck`, розмір файлу |
| A8 | Емулятор на копії реальних даних: запис, заміна, конструктор, каталог, прогрес — без збоїв | Ручний прогін зі скріншотами |
