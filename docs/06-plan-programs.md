# План: багатотижневі програми й англійська для нових екранів

Складено 18.09.2026.

## Навіщо

**Програми.** Зараз додаток добре відповідає на питання «що робити сьогодні», але
не на «куди я йду наступні два місяці». Саме цим тримають людей Strong і Boostcamp:
ти обираєш програму, і вона щотижня сама піднімає навантаження. У нас для цього вже
є все, чого немає в них: бібліотека з рівнями, заміни під обладнання й травми,
розпізнавання назв і калорії. Бракує лише шару «тиждень за тижнем».

**Англійська.** Нові екрани писались українською в тексті коду: підказки замін
(«те саме, але з гантелями»), заголовки блоків конструктора, техніка вправ. З
англійським інтерфейсом додаток виглядає наполовину перекладеним.

## Частина A. Програми

### A1. Модель

```ts
interface ProgramTemplate {
  id: string;                    // 'linear_strength'
  nameUk: string; nameEn: string;
  weeks: number;                 // 6–12
  daysPerWeek: number;           // 3–4
  focus: Focus;                  // сила / маса / витривалість
  level: Level;                  // для кого
  equipment: Equipment[];        // що потрібно; без цього програму не пропонуємо
  summaryUk/summaryEn: string;   // два речення: як це працює
  days: ProgramDay[];            // шаблон тижня
  progression: Progression;      // як росте навантаження
}

interface ProgramDay {
  titleUk/titleEn: string;       // «День A — присід і жим»
  slots: ProgramSlot[];
}

interface ProgramSlot {
  exerciseId: string;            // основний рух програми
  role: 'main' | 'accessory' | 'core' | 'conditioning';
  sets: number; reps: number;
  /** Від чого рахувати вагу: від робочої ваги цього руху. */
  intensity?: number;            // 0.65–0.95 від робочої ваги; без нього — за схемою
}

type Progression =
  | { kind: 'linear'; stepKg: number; deloadEveryWeeks?: number }   // +2.5 кг щотижня
  | { kind: 'volume'; addSetEveryWeeks: number }                    // +1 підхід
  | { kind: 'wave'; intensities: number[] };                        // 65/75/85, потім спад
```

Назви програм — власні описові («Лінійна сила», «Обʼєм на масу»), без чужих
торгових марок. Самі методи (лінійна прогресія, хвиля відсотків) — загальне надбання.

### A2. Рушій

- **A2.1** `prescriptionFor(slot, week, base)` — скільки підходів, повторів і кілограмів
  на конкретному тижні. База — робоча вага користувача з історії (`lastResults`), якщо
  її немає — просимо ввести один раз при старті програми.
- **A2.2** Тиждень розвантаження: обʼєм і вага падають (≈60% від робочої), щоб не
  накопичувалась втома.
- **A2.3** `programDayToExercises(day, week, base, resolver)` → готові `ExerciseLog[]`
  для форми запису — тим самим механізмом, що конструктор.
- **A2.4** Якщо вправи програми немає під обладнання користувача — підбираємо заміну
  наявним рушієм (`findSubstitutions`) і показуємо, що саме замінили.

### A3. Стан програми

`@alpha_trainer:active_program`:
```ts
{ templateId, startedAt, baseWeights: Record<exerciseId, kg>, done: string[] }  // 'w2d1'
```
- **A3.1** Одна активна програма за раз; почати нову — питаємо підтвердження.
- **A3.2** «Пропустив день» не ламає програму: наступний день просто наступний
  непройдений.
- **A3.3** Ключ додається в `backup.ts` ALL_KEYS.

### A4. Екрани

- **A4.1 Каталог програм** (`app/programs/index.tsx`): картки — назва, тижні, дні на
  тиждень, для кого, чи вистачає обладнання.
- **A4.2 Картка програми** (`app/programs/[id].tsx`): опис, розклад тижня, прев'ю
  прогресії («тиждень 1: 3×5 @ 80 кг → тиждень 6: 3×5 @ 92.5 кг»), кнопка «Почати».
- **A4.3 Активна програма** — на головному екрані: «Тиждень 2, день A» і кнопка
  «Почати тренування»; прогрес «5 із 18 днів».
- **A4.4** Після збереження тренування день позначається пройденим.

### A5. Що дати в коробці

1. **«Лінійна сила»** — 8 тижнів, 3 дні, A/B, +2.5 кг щотижня, розвантаження на 8-му.
2. **«Обʼєм на масу»** — 6 тижнів, 4 дні, верх/низ, +1 підхід кожні 2 тижні.
3. **«Кросфіт-цикл»** — 6 тижнів, 3 дні: силова частина + метокон, хвиля 70/80/85%.
4. **«Власна вага»** — 6 тижнів, 3 дні, без обладнання, прогресія через складнішу
   варіацію вправи (бібліотека це вміє через `easierThan`).

### A6. Перевірка

- прогресія рахує ваги детерміновано, розвантаження нижче попереднього тижня;
- програма ніколи не пропонує вправу, якої не дозволяє обладнання чи бережені зони;
- день програми перетворюється на запис із тими самими id, що й конструктор;
- пропущений день не ламає нумерацію;
- усі тексти програм мають обидві мови.

## Частина B. Англійська для нових екранів

### B1. Що зараз лише українською

| Місце | Приклад |
|---|---|
| `substitutions.ts` | «те саме, але з гантелями», «не навантажує плече» |
| `builder.ts` | «A. Основна — ноги», «AMRAP 12 хв» |
| `prescriptions.ts` | «5×3–5, відпочинок 2:30» |
| екрани | конструктор, картка вправи, розпізнавання, джерела |
| дані бібліотеки | підказки техніки (≈450 рядків) |

### B2. Підхід

- **B2.1** Сервіси не форматують текст самі: повертають **код** і дані
  (`{ kind: 'equipment_swap', equipment: 'dumbbell' }`), а рядок збирає UI через `t()`.
  Так переклад не доведеться робити двічі.
- **B2.2** Нові рядки екранів — у `services/i18n.ts`, обидві мови.
- **B2.3** Підказки техніки: додаємо `cuesEn?` у бібліотеку й `cuesOf(ex, lang)` з
  відкотом на українську. Перекладаємо найуживаніші вправи, решта чекає.
- **B2.4** AI відповідає мовою інтерфейсу: у промпт іде «Answer in English», коли
  вибрано англійську.

### B3. Перевірка

- тест: жодного українського рядка в `substitutions.ts`, `builder.ts`,
  `prescriptions.ts` поза коментарями;
- тест: кожен ключ i18n має обидві мови;
- тест: `cuesOf` віддає англійську, коли вона є, інакше українську.

## Незалежна перевірка плану

| # | Зауваження | Рішення |
|---|---|---|
| П1 | Програма з фіксованими вправами стане непотрібною тому, у кого немає штанги | Кожна програма декларує обладнання; у каталозі видно «потрібна штанга», а всередині працює звичайна заміна. Плюс програма «Власна вага» без інвентарю |
| П2 | Робочої ваги на старті може не бути (нова вправа) | Питаємо один раз при старті програми, підставляючи оцінку з історії, де вона є. Без ваги показуємо цільовий RPE, як у конструкторі |
| П3 | Чужі торгові марки в назвах програм (5/3/1, StrongLifts) | Назви власні, описові; методи загальновідомі |
| П4 | Переклад 450 підказок техніки — це окремий тиждень роботи | Спершу механізм із відкотом, далі найуживаніші вправи.半-перекладеність краще, ніж відсутність механізму |
| П5 | Зміна сигнатур у `substitutions.ts` зачепить наявні екрани | Повертаємо і код, і готовий український рядок (`reason` лишається) — екрани мігрують поступово |
| П6 | Активна програма й AI-план конкурують за головний екран | Програма головніша: якщо вона активна, показуємо її; AI-план лишається окремою карткою нижче |
| П7 | Обсяг: A+B разом — це багато. Чи не краще спершу випустити A? | Так. Порядок: A (рушій → дані → екрани → головна) → перевірка → реліз 1.4.0. Потім B окремим релізом 1.5.0 |
| П8 | Прогресія на 8 тижнів уперед може виявитись нереальною (людина застрягне) | Даємо кнопку «не вийшло» на тижні: вага відкочується на 10% і тиждень повторюється — це те, що роблять живі тренери |

**Порядок:** A2 рушій → A1/A5 дані → A3 стан → A4 екрани → перевірка → реліз 1.4.0.
Далі B2.1 коди замість рядків → B2.2 i18n екранів → B2.3 підказки → реліз 1.5.0.
