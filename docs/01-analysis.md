# Аналіз: що потрібно, щоб тренувальна частина стала потужною і якісною

_2026-09-17. Основа — код у репозиторії та реальні дані користувача (агреговано, копія з телефона від 16.09)._

## 1. Запит користувача

1. Обирати вправи з бібліотеки й бачити, як вони виглядають (картинки без проблем з авторським правом).
2. Складати грамотне тренування з прикладами вправ.
3. Замінювати вправу, яку зараз не можу або не хочу робити. Заміни — не будь-які, а грамотно
   підібрані: простіша вправа або інша варіація того самого руху.
4. Усе має рахуватись і відображатись правильно.

## 2. Як додаток використовується насправді

| Факт | Значення |
|---|---|
| Тренувань | 30 (23 CrossFit, 2 силові, 2 біг, 1 йога, 2 інше) |
| Тренувань із суперсетами | 25 з 30 — кросфіт-блоки записуються суперсетами |
| Різних назв вправ | 152 на 286 записів |
| Назв, які впізнає бібліотека | **12** (54 записи з 286, 19%) |
| Найчастіші | присідання 16, бурпі 15, біг 11, гребля 10, станова 8, присідання зі штангою 7, відтискання 7, підтягування 7 |
| «Присідання» | 16 записів, **усі без ваги** → це присідання з власною вагою |
| Кардіо у кросфіті | «Біг 3 підх. 0.2 км», «Гребля 6 підх. 16 ккал» — дистанція/ккал **на підхід** |
| Дублі написання | front squad / front squat, sit up / сітап, крокуючі випади / крокуючий випадок, стільчик біля стіни / під стінкою / присідання під стіною |
| Профіль | рівень intermediate; обладнання: штанга, зал, гантелі, турнік, гирі, брусся, доріжка, скакалка |
| Шаблонів | 0 |
| Збережений AI-план | 8 «днів»; серед «вправ» — «17:00 - Кросфіту», «Тренування верхньої частини тіла:» |

Висновок: у додатку немає поняття «вправа» — є лише рядок, який людина набрала. Усе, що
залежить від вправи (прогрес, рекорди, баланс м'язів, калорії, а тепер ще заміни й конструктор),
змушене вгадувати за текстом, і вгадує лише в 19% випадків.

## 3. Що вже добре і не повинно зламатись

- Запис тренування: суперсети (групування заднім числом, переміщення блоками), піраміди (`setsDetail`),
  редагування вправ, таймер відпочинку, калькулятор блінів, режим шаблону.
- Калорії по вправах під параметри профілю (`services/calories.ts`), 101 unit-тест.
- Прогрес: 1RM, тоннаж, об'ємні орієнтири, баланс м'язів, рекорди, досягнення.
- AI-тренер і нутриціолог, офлайн-зберігання, резервна копія, оновлення через GitHub Releases.

## 4. Проблеми й прогалини

### P0 — блокують запит

1. **Немає ідентичності вправи.** `ExerciseLog` зберігає лише `name`. Прогрес/рекорди групуються
   за текстом → дублі розбивають історію; аналітика класифікує regex-ами.
2. **Бібліотека не знає нічого, крім групи м'язів і типу.** Немає рухового патерну, обладнання,
   складності, зв'язків «простіше/складніше», підказок техніки, картинок. Немає кросфіт-рухів
   (сітап, трастер, wall ball, стрибки на бокс, лижний тренажер, байк, кільця…).
3. **Пошук у бібліотеці — точний підрядок без синонімів.** «Бурпі» не знаходить «Берпі»,
   «гребля» — «Гребний тренажер». Вибір повертає рядок, а не вправу.
4. **Немає замін і конструктора тренування.**
5. **Немає ілюстрацій.**

### P1 — знижують якість

6. **AI-план — вільний текст, розібраний regex-ами.** Вправи не прив'язані до бібліотеки,
   у список потрапляє сміття; «Записати сьогоднішнє тренування» відкриває порожню форму.
7. **Профіль обладнання грубий.** 10 варіантів, немає гребного/байка/лиж/боксу/м'яча/кілець/резинок;
   «Тренажерний зал» нічого не каже про конкретне обладнання. Немає обмежень (біль, травми).
8. **Мова назв вправ за замовчуванням — англійська**, а користувач пише українською.
9. **Форма вправи продубльована** в `app/workout/log.tsx` і `app/workout/[id].tsx` (~200 рядків).
   Кожна нова дія з вправою множиться на два й може розійтись.

### P2 — поза цією ітерацією

10. Нутриція, вода, самопочуття, досягнення — працюють, окремого запиту немає.
11. Синхронізація між пристроями, інтеграція з годинником/Google Fit.
12. UI-тести (зараз лише сервіси).

## 6. Ілюстрації: дослідження джерел

Критерій користувача — «щоб не було проблем потім з авторськими правами». Важливо: репозиторій
**публічний**, APK публікується в GitHub Releases, тобто картинки **поширюються публічно** —
«особисте використання» не рятує, потрібна ліцензія на поширення.

| exercises-dataset (1324 GIF) | GIF © Gym visual, «reuse is governed by Gym visual's Terms» | ❌ Не можна |

| Генерація AI | Статус авторства неоднозначний; головне — часто неправильна техніка | ⚠️ Не для навчання техніки без ручної перевірки |

**Що вимагає CC BY-SA 4.0 і як виконати:**
- Вказати автора, джерело, ліцензію з посиланням і що змінено → екран «Джерела ілюстрацій» у
  додатку + `assets/exercises/ATTRIBUTION.md` у репозиторії.
- ShareAlike: змінені картинки (конвертація, розмір) поширюються теж під CC BY-SA 4.0. На код
  додатка це не поширюється — картинки лишаються окремими творами у складі збірки.
- Не додавати технічних обмежень (DRM) — їх немає.

**Спостереження щодо якості:** середні кадри деяких вправ намальовані товщою лінією, ніж
крайні (напр. віджимання, станова) — треба переглянути на етапі реалізації й за потреби
анімувати лише крайніми кадрами. Покриття: немає трастера, стрибків на бокс, wall ball, сітапа,
олімпійських рухів — для них картка показує підказки техніки й посилання на відео.

**Залишковий ризик:** репозиторій Workout Guide новий (серпень 2026); розширення зроблені автором
і ліцензовані ним під CC BY-SA 4.0. Мітигація — усі картинки підключені через одну мапу, їх можна
вимкнути чи замінити одним змінним файлом.

## 7. Ризики ітерації

| Ризик | Мітигація |
|---|---|
| Помилки в розмітці бібліотеки → «грамотні» заміни стануть неграмотними | Схема з обов'язковими полями, тест цілісності, тести замін на топ-вправах користувача, незалежне рев'ю |
| Зміна чисел у прогресі після прив'язки історії | Порівняння «до/після» на копії реальних даних; зміни лише там, де покращилось розпізнавання |
| Втрата даних при міграції | Жодного переписування записів: зв'язки назва→вправа зберігаються окремо |
| Розмір APK | Лише потрібні кадри, WebP ~320px; бюджет +10 МБ |
| Розростання дубльованої форми | Нові дії — через спільні компоненти; повний рефакторинг форми — окремо |
